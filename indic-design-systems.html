Indic design systems · the family

India, by design

A family of original design systems — one per era and, in time, one per state — each drawn from India's own heritage: the polished Mauryan pillar, the Gupta temple, the Ajanta fresco, and the living craft of every region. Not a theme bought off a shelf; India's visual grammar, rebuilt as reusable systems. Every system is documented the same way — on the five tiers of Atomic Design, with live components, tokens, and the reasoning behind each decision.

The method — every system, the same spine

One scaffold, many skins

Each system is documented on Atomic Design: Tokens (the raw colour/type/space/elevation) → Atoms (buttons, inputs, badges) → Molecules (fields, alerts, tabs) → Organisms (tables, dialogs, card grids) → Templates (the page layouts). The components live once in styles.css and are painted entirely by tokens — so a new system is a new token set on the same atoms, not a new codebase. That is why we can grow to a design system per state without the work exploding.

We benchmarked coverage against Oracle JET and Google Material — took their thoroughness in states, density, and elevation — and then added the thing both of them lack: the design reasoning, and a home in India's own heritage. Each system page carries the "why this is an atom, not a molecule" that a component dump never explains.

Registers — mood within a system

Pick the register per context

A single system can carry more than one mood. Within Mauryan: the stone-and-sky register is the skeleton (nav, map, data); the Gupta register — red sandstone & Ajanta — is the soul (long-form, heritage); the dark temple-interior register (maroon + gold-leaf) is for 3D pages and the engines hub. Same atoms, different tokens. Try the skin switcher above.
